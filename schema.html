이 웹페이지의 데이터 구조 한눈에 보기

이 사이트의 파일 구조부터, seoul-apt-latest.csv가 어떻게 data/dashboard_data.json으로 압축되고 dashboard.html이 그 데이터를 어떻게 읽는지까지 — 파일 지도 하나, 다이어그램 두 장, 표로 정리합니다.

01 · Site map

페이지 구조

이 사이트는 정적 파일 8개로 이루어져 있습니다. 코드 2개가 데이터를 만들고, 문서 3개가 그 데이터를 화면과 글로 보여줍니다.

sesac-web/ ├── seoul-apt-latest.csv ← 원본 데이터, 32만 행 · 27.6MB ├── code/ │ ├── build_data.py ← CSV → dashboard_data.json 집계 스크립트 │ ├── analyze.py ← 자치구별 매매-전세 갭 분석 │ └── base.py ← CSV를 한글 컬럼명으로 읽는 예제 ├── data/ │ └── dashboard_data.json ← 대시보드가 실제로 fetch하는 집계 데이터 ├── index.html ← 메인 페이지 (자기소개 + 대시보드 링크) ├── dashboard.html ← 부동산 대시보드 (예산/면적/거래유형 → 랭킹·추이) ├── schema.html ← 지금 보고 있는 이 페이지 ├── PRD.md ← 대시보드 기획 문서 └── for_starters.md ← 세션 전체를 설명하는 초보자용 문서

화면 두 개(index.html, dashboard.html)는 원티드 Montage 디자인 시스템을 따르고, 이 페이지(schema.html)만 별도의 에디토리얼 디자인 시스템으로 만들어져 있습니다 — "데이터 구조를 도해로 설명한다"는 이 페이지만의 목적에 맞춰 의도적으로 다른 톤을 골랐습니다.

02 · Pipeline

데이터가 흘러가는 경로

원본 CSV는 브라우저가 직접 읽지 않습니다. Python 스크립트가 미리 집계해 작은 JSON을 만들고, 웹페이지는 그 JSON만 받아 옵니다.

CSV → 집계 스크립트 → 집계 JSON(focal) → 화면. 화살표는 z-order상 노드보다 먼저 그려집니다.

03 · Nested containment

dashboard_data.json의 중첩 구조

바깥쪽일수록 범위가 넓고, 안쪽일수록 구체적입니다. 가장 안쪽 칸(면적구간)이 실제 숫자 4개를 담고 있는 최소 단위입니다.

data[자치구][거래유형][연월][면적구간] → {count, sum_price, sum_area, sum_rent}
